## 5. 正式部署与兼容契约

### 5.1 当前入口与拟新增入口

现有 `migration:status／run／verify`支持有合法历史的库；没有已验收的正式空库初始化。`migration:drill:*`会清表，只可用于显式可丢弃环境的额外演练。

拟新增 `database:deploy`，**尚未实现，下面不能现在执行**。名称如经确认调整，package.json、测试、SOP必须同时更新。

```bash
# 在 backend 执行，<...>必须替换为核准目标；不是默认开发库
npm run database:deploy -- --mode init --config-file <私密配置> --database <目标库> --confirm-database <目标库>
npm run database:deploy -- --mode upgrade --config-file <私密配置> --database <目标库> --confirm-database <目标库>
```

一键指“准备后一个正式命令完成建库／升级及校验”。MySQL安装与启动、连接账号／权限、Node/npm和私密配置是前置，不自动改系统服务、AppArmor、Docker权限或启动API／Worker。

### 5.2 init

- 必须显式配置及目标确认；无隐式.env回退，密码不出现在参数或日志。运行强制 `synchronize=false`。
- 库不存在：先在明确服务器连接核对版本、目标、权限及互斥，再只创建指定库；连接后核对实际 `DATABASE()`，建立合法迁移元数据并执行完整链。
- 库已存在：只有确为空库可首次初始化；已完整匹配终态允许验证后无变化返回。旧业务表、无历史非空库、半迁移或未知对象停止，不能DROP／TRUNCATE或伪造记录。
- 互斥覆盖检查、建库、建表和后验；统一init／upgrade锁语义，防止初始化窗口竞争或嵌套锁互相等待。
- 没有建库权限明确失败，或先由维护人员建空库；不自动换库。初始化身份与应用运行身份分开，不要求长期root。

### 5.3 upgrade及失败收尾

- 先停写，升级前备份在独立副本实际还原验证；确认目标与许可后复用历史前缀、结构漂移、半迁移预检，只运行pending。
- 保留现有14／24等前缀检查的安全含义；本期必验30态及31态副本到新终态。其他原支持路径受影响时补验或明确经评审的受控路径，不静默破坏旧支持范围。
- 终态核验类型／默认／NULL、键及列序、FK、CHECK、生成列、允许回填及pending=0。重复执行0条；最终迁移数N／业务表数M由S1确定。
- MySQL多条DDL不能靠普通事务保证整批回滚。失败保存现场，只读诊断，不自动down、DROP、删历史、Seed、清库或盲目重试。
- 连接、锁释放、销毁失败不得吞掉；主错和收尾错并列保留，全部成功后才打印成功文案及退出0。结果不明先核对实际对象与历史。

## 7. 验证命令与停止规则

当前已有静态入口，在`backend`执行；本轮仅写计划，没有运行以下测试：

```bash
npm run typecheck
npx tsc -p tsconfig.spec.json --noEmit
npm run lint:architecture-fixtures
npm run lint:usecase-normalize-guard
npm run capability:docs:check
npm run test:unit -- --runInBand
npm run build
```

对变更文件运行ESLint（不加`--fix`）及Prettier check；`npm run lint`当前含自动修复，不能当只读检查。仓库根运行`git diff --check`，未跟踪文件单独纳入校验。

旧库四步必须先有核准配置、备份／还原、停写和写入授权；`migration:verify`是终态检查，不作为旧态必须通过的升级前检查：

```bash
npm run migration:status -- --config-file <私密配置> --database <升级副本>
# 下行是本期拟实现入口，现在不可执行
npm run database:deploy -- --mode upgrade --config-file <私密配置> --database <升级副本> --confirm-database <升级副本>
npm run migration:verify -- --config-file <私密配置> --database <升级副本>
npm run database:deploy -- --mode upgrade --config-file <私密配置> --database <升级副本> --confirm-database <升级副本>
```

实库规格按当前runner支持的真实路径逐个登记，不能只在临时脚本运行。完整core在独占测试库运行：

```bash
E2E_DOTENV=<核准的隔离配置> \
E2E_SKIP_DB_CLEANUP=true E2E_ALLOW_DB_CLEANUP=0 \
E2E_ALLOW_PHYSICAL_CLEANUP=1 npm run test:e2e:core
```

上述环境变量不是任意库授权。执行前核对配置优先级、实际实例与`DATABASE()`、Redis收尾；共享Redis不能FLUSHDB。新增部署工具不要求Redis，core如需Redis则独立准备获准环境。

停止并报告：目标不明／未获写入授权；源稿缺失或冲突；需扩大接口／Capability范围；未知或半迁移；非目标数据改变；所有权／引用无法核验；清理或连接收尾失败；远端无法确认时保留未确认项。缺实库条件时可完成静态部分，但相应门禁保持未完成。
