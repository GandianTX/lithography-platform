## 1. 缺陷现状（修复前）

| 环节 | 位置 | 行为 |
| --- | --- | --- |
| 裁决（只读采用） | `backend/src/usecases/local-runtime/resolve-sync-conflict.usecase.ts:315-318` | `planCloudConflictAlignment` 返回 `view-only` ⇒ **直接 return，不写业务记录、不改历史**（R066／R068） |
| 落裁决事实 | `backend/src/modules/lithography/sync-conflict.service.ts:139-168` | `decision='CLOUD'`、`status='RESOLVED'`，并把 `local_version` 推到云端版本 |
| 冲突详情页 | `backend/src/usecases/local-runtime/get-sync-conflict.usecase.ts:63-64` | `decision==='CLOUD' && status==='RESOLVED'` ⇒ `localSnapshot` 换成 `cloudSnapshot` ⇒ **冲突页能看到云端内容** |
| **来源页（工单详情）** | `backend/src/modules/lithography/queries/repair-request.query.service.ts:241-314` | **只读 `repair_request` 表** ⇒ 与 `sync_conflict` 毫无关联 ⇒ **读回的还是本地旧内容** |

⇒ 用户在冲突页选完「使用云端」、点「打开来源页」，看到的仍是**本地 A** 而不是他选的**云端 B**
—— 这正是 P1-4。

**为什么不能简单"把云端内容写回业务行"**：已结单工单不得反写
（`resolveSyncConflictReadOnly`：已删除／下架／冻结／结单一律拒绝反写）；
R068 要求"只对齐本地有权视图，不取得新编辑权"、"不 UPDATE 云端原记录或覆盖原始历史"；
写回会新增修订行 ⇒ **篡改原业务历史**。⇒ 必须做**读取时的受控只读投影**。

## 2. 修复内容

### 2.1 判定口径（core 纯策略，可测）

新增 `backend/src/core/local-runtime/policy/sync-conflict-readonly-view.policy.ts`
（`planReadOnlyCloudAdoptedView`），只有**同时**满足下列条件才投影：

1. 资源类型是工单；
2. 冲突已裁决为「使用云端」且 `status='RESOLVED'`；
3. 来源记录**已结单**（`isRepairRequestEnded`）；
4. **业务行当前受控字段 == 冲突登记的本地快照**（正文／处理结果／处理状态逐项相等）
   ⇒ 证明这次裁决**没有改写业务行**（只读采用），而不是用户后来又编辑过；
5. 云端快照可解析且受控字段自洽（状态必须由结果推导，不自洽即拒绝）。

投影口径：**云端有则用云端、云端没有则保留本地原值**（与业务对齐写入器口径一致
⇒ 对"业务对齐"场景同样是幂等的，不会重复覆盖）。

### 2.2 为什么用"内容事实"而不是新增标记列

`local_version`（本地同步版本）与 `cloud_version`（云端版本）来自**两个不同序列**，
大小**不可比** ⇒ 不能用 `localVersion < cloudVersion` 当"只读采用"标记；
而新增列需要迁移 + `migration-schema-contract` 登记（改动面大、且触碰已接受基线）。
用内容事实判定：**零迁移**，且天然覆盖"用户后来又编辑"的情况。

### 2.3 读取侧接入

- `SyncConflictQueryService.readLatestByRecordUuid()`：按 `(resourceType, recordUuid)`
  读取**最新一条**冲突（含两份快照）——旧裁决不得盖过更新的冲突现状；
- `RepairRequestQueryService.resolveReadOnlyCloudView()`：在**权限判定通过之后**叠加投影，
  并复核**公司口径**（冲突登记公司必须落在工单的归属公司或服务公司内 ⇒ 跨公司不投影）；
- `findDetail()` 的 `contentMd` / `handlingResult` / `handlingStatus` 三个字段按投影结果返回；
  **其余字段（故障描述、结单原因、附件、时间线等）保持业务行原值**。
