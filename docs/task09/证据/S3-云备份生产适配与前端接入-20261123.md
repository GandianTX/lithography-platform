## 2. 云备份生产适配（后端）

新增目录 `backend/src/infrastructure/cloud/`：

| 文件 | 职责 |
| --- | --- |
| `local-backup-cloud.config.ts` | 服务端配置形状（地址／凭据／超时）＋ 请求头常量；**不硬编码** |
| `http-local-backup-cloud.client.ts` | 受控 HTTP 客户端：凭据只在请求头、失败一律映射为**受控失败码** |
| `http-local-backup-uploader.ts` | 上云适配：`POST /backup-packages`（multipart），要求云端同时给出**云端对象引用 ＋ 完整回执** |
| `http-local-backup-cloud-provider.ts` | 云包读取适配：`GET /backup-packages`（清单）、`GET /backup-packages/{id}/content`（字节） |
| `local-backup-cloud.module.ts` | 装配：**地址或凭据缺失 ⇒ 两个端口都不注册** |

### 2.1 协议（与云端约定）

- 上云：`multipart/form-data`，字段 `backupId`／`organizationId`／`installationId`／`manifestChecksum`／`byteSize`，
  部件 `manifest`（清单原文）、`payload`（加密载荷字节）、`files/<相对路径>`（业务原件字节）；
  成功响应必须同时含 `cloudReference` 与 `receipt`，**缺任一即按形态非法失败关闭**。
- 清单：`GET /backup-packages?organizationId=X` → `{ "packages": [...] }`；
- 下载：`GET /backup-packages/{packageId}/content?organizationId=X` → 二进制字节。

### 2.2 纪律（与既有实现口径一致）

- **不伪造成功**：云端未返回完整回执即按失败处理 ⇒ 手动清理仍然是「无完整云回执 ⇒ 零清理」；
- **不暴露密钥**：凭据不进日志、不进包、不经 API 返回；只出现在 `Authorization` 请求头；
- **用途固定**：`X-Cloud-Purpose: CLOUD_BACKUP`——上云不得拿业务同步授权充数
  （见 `core/local-runtime/policy/local-credential-purpose.policy.ts`）；
- **失败关闭**：网络异常／超时／4xx／5xx／响应形态非法 → 受控失败码，
  原始异常只作为 `cause` 保留，不回显自由文本与本机绝对路径；
- **不注册即不可用**：地址或凭据缺失时端口不提供实现，调用方按受控原因码
  `CLOUD_PACKAGES_UNAVAILABLE` 失败关闭（**不伪造可用包**）。

### 2.3 装配位置

- API 进程：`usecases/local-runtime/local-runtime-usecases.module.ts` 导入 `LocalBackupCloudModule`
  （云包清单／下载的 GraphQL 与 REST 入口都在 API 侧）；
- Worker 进程：`bootstraps/worker/worker.module.ts` 导入同模块（自动上云在 Worker 侧执行）；
- 环境变量（新增，已写入 `backend/env/.env.example`）：
  `LOCAL_BACKUP_CLOUD_BASE_URL`、`LOCAL_BACKUP_CLOUD_CREDENTIAL`、`LOCAL_BACKUP_CLOUD_TIMEOUT_MS`。

### 3.1 纪律

- **下载权限 ≠ 恢复权限**：下载只给字节，界面明确标注「下载不等于恢复」；
- **受理 ≠ 恢复**：执行入口只在**预检通过且受理成功**后出现，且限管理员；
- **失败不伪装成功**：执行结果按服务端终态呈现——`status=FAILED` 或 `holdRetained=true` 时
  明确提示「设备仍处于停写停传（已保留保护副本）」，绝不显示为"已恢复"；
- **云服务未接入时如实呈现**：清单读取失败按失败态呈现，不展示伪造的可用包。
