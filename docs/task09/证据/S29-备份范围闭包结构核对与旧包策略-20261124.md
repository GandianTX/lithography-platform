## 2. 修掉的真实缺陷：旧包缺**范围根表** ⇒ 静默部分恢复

- 位置：`backend/src/modules/lithography/local-restore-record.writer.ts` 的 `checkScopeConsistency`；
- 缺陷：原检查只对**载荷中已存在的父表**核对子表；载荷若缺一张**范围根表**，
  该表**既不清空、也不写回、也不核验** ⇒ 恢复结束后库处于"一半新一半旧"的自相矛盾状态
  （**静默部分恢复**）。既有单测只覆盖"缺子表"，该路径**无覆盖**；
- 修复：追加第三段检查——**范围根表必须齐备**，缺失即显式拒绝（失败关闭），文案说明"与本机支持的数据范围不一致，请重新生成备份"；
- 既有拒绝口径**未变**："缺子表"仍在同一检查中优先命中（既有断言与既有证据结论不受影响）；
- 单测：新增「旧包缺**范围根表** ⇒ 失败关闭（不静默部分恢复）」1 例；
  `local-restore-record.writer.spec.ts` **25/25**、`protected-backup.policy.spec.ts` 合计 **44/44** 通过。

## 3. 第 2 条：旧包策略与实际影响（**待维护者裁定**）

### 3.1 现状（既有取舍，非本轮新增）

| 情形 | 现有行为 | 位置 |
| --- | --- | --- |
| 旧包缺**子表** | **显式拒绝**，文案含"重新生成备份"；写入前失败关闭，无半写 | `local-restore-record.writer.ts` `checkScopeConsistency` |
| 旧包缺**范围根表** | **本轮起显式拒绝**（此前静默部分恢复） | 同上（新增第三段） |
| 清单解析层 | **不要求覆盖当前全部范围表**（否则已落盘旧包全部无法解析） | `protected-backup.policy.ts` 清单解析 |
| 版本闸门 | 仅 `BACKUP_MANIFEST_SCHEMA_VERSION=1`；**无迁移版本／库结构版本校验** | `protected-backup.policy.ts` |
| 兼容开关 | **不存在**（全仓无"允许缺表继续"） | — |

### 3.2 实际影响（用户可见）

使用旧格式备份包的用户**无法直接恢复**，必须**重新生成备份包**（成本＝读取本机数据区＋落盘）。
该行为变化在既有证据 `S8` §5／§8.5 已记录为"**需维护者确认是否接受**"，**本轮不自行认定已批准**。

### 3.3 可审核的方案（供维护者裁定，本轮只实现零风险项）

| 选项 | 内容 | 风险 | 状态 |
| --- | --- | --- | --- |
| **A** | 维持"显式拒绝 + 明确文案 + 重新生成指引" | 无 | **现状（本轮保持）** |
| **B（推荐）** | 清单增加**生成侧范围版本号**（如 `generator_scope_version`），**预检阶段**即给出"包版本落后、需重新生成"的**可读原因**（比写入阶段失败更早、更易懂） | 低：只加清单字段与预检提示，不改变"拒绝"方向 | **待裁定（本轮未实现）** |
| **C** | 按表降级恢复（跳过缺失表并列出被跳过表） | **高**：回到"部分恢复＝自相矛盾状态"，与本轮刚修掉的静默路径冲突 | **不建议** |

⇒ 需要维护者确认的是 **3.2 的用户可见取舍（旧包需重新生成）是否接受**；若接受，建议再裁定选项 B。

## 5. 遗留与边界（如实登记）

1. **队列项未覆盖非空场景**：隔离库无待传上传任务，`queue=0` ⇒ "队列随恢复正确重放"只验证了**空集**；
   非空队列需要先造待传任务（涉及第 09/10 项的队列口径），本轮未做。
2. **新增列无版本闸门**：迁移新增列时，旧包行缺该属性 ⇒ 可空列取 DB 默认值（非空列则写回失败但文案不可区分）；
   修法见 §3.3 选项 B（清单版本号），**待维护者裁定**。
3. **两设备两公司的"第二家公司"未在本轮实测**：两套隔离库都只有公司 1；
   "不同公司共享引用／外部引用"的结构判定已由 A1b／A3 给出（结构上不可能），但**跨公司共享同一业务行的实测**未做。
4. **备份 ID／目录唯一性与保护副本碰撞**：由既有 selfcheck 的"预检通过并生成保护副本"断言与
   `backup_restore_run`／`backup_asset` 逐次唯一 ID 间接覆盖；**同目录重复预检的碰撞拒绝**未单列断言（如实登记）。
5. 第 01/02/03 项遗留（业务写入的"检查冻结→实际写入"窗口、`forceReleaseForRecoveryIncident()` 无对外入口）不在本项范围。
