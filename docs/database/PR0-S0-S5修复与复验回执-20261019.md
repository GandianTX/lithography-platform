## 二、修复项回执（F1～F4：分记「已修复」与「已验证」）

### F1 审核队列排序（计划 R1）

**已修复**

- `backend/src/modules/lithography/queries/content-submission.query.service.ts`：审核队列排序改为类型化常量 `REVIEW_LIST_ORDER: FindOptionsOrder<ContentSubmissionEntity> = { lastSubmittedAt: 'DESC', id: 'DESC' }`（对应数据库 `last_submitted_at`；此前使用实体上不存在的 `submittedAt`，运行期构造查询即失败）；本人列表 `MINE_LIST_ORDER` 同型约束（`updatedAt DESC, id DESC`）。不为改名新增数据库列。
- `backend/src/usecases/content-submission/list-review-queue.usecase.ts`：排序口径注释同步 `last_submitted_at DESC, id DESC`。

**复现测试**

- `content-submission.query.service.spec.ts` 3 个用例：旧排序字段 `submittedAt` 在真实 Entity 元数据上构造 QueryBuilder 即失败（复现锚点）；`REVIEW_LIST_ORDER` / `MINE_LIST_ORDER` 在真实元数据上有效。不连接数据库、不以 mock 返回列表替代。

**已验证**

- 单测：`npm run test:unit -- content-submission.query.service` → 3 用例通过。

- 验收口径对照：实际 ORM 可构造查询 ✓；排序与业务时间 `last_submitted_at` 一致 ✓；默认待审、组织过滤、分页与总数口径保持不变 ✓。
