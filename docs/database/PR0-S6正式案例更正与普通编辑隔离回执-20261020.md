## 一、S6 交付范围与实现

### S6-1 案例字段格式化单一真源（公共契约）

- 新增 `backend/src/usecases/common/fault-case-fields.contract.ts`：`formatFaultCaseReferenceContent` 从投稿域提炼为公共契约（`usecases/common/**/*.contract.ts` 为跨域共享官方豁免位）。
- 段落顺序固定：错误码 / 故障现象 / 触发条件 / 复现步骤 / 排查过程 / 处理措施 / 处理状态 / 处理结果，`join('\n\n')`；空值段落省略；状态标签 UNRESOLVED=未解决、IN_PROGRESS=处理中、RESOLVED=已解决。
- 发布链（`approve-content-submission.usecase.ts`）与更正链（`update-reference-document-case.usecase.ts`）共用同一真源；CS 域 `content-submission-fields.normalize.ts` 保留再导出，既有导入路径兼容、不产生跨域直导。

### S6-2 RD 域案例字段 normalize / 合并 / 校验

- 新增 `backend/src/usecases/reference-document/reference-document-case-fields.normalize.ts`：
  - 字段 normalize：标题/说明/机型文字/处理状态/受限文本（错误码、触发条件、现象、复现步骤、排查过程、处理措施、处理结果），超长统一报 `「字段名不能超过 N 个字符」`；
  - `mergeCaseDetailPatch`：undefined=保持原值、null=清空、新值=覆盖；处理状态现值复核走 `normalizeEnumValue`，值域外抛 `INPUT_NORMALIZE_ERROR.INVALID_ENUM_VALUE`（与数据库 CHECK 同口径）；
  - 断言：`assertCasePatchHasEditableField`（空补丁拒绝）、`assertCaseCorrectionPresent`（合并后必填非空）、`assertCaseResolutionWhenResolved`（RESOLVED 必须有结果）、`assertCaseModelExclusive`（机型 ID 与机型文字互斥；替换需同一补丁清空另一侧）。
- `reference-document.types.ts` 扩展：`UpdateReferenceDocumentCaseCommand`、案例补丁字段类型、`ReferenceDocumentCaseMutationResult`（`{id, updatedAt}`）。

### S6-3 服务扩展

- 新增 `backend/src/modules/lithography/reference-document-case-detail.service.ts`：`insertCaseDetail`（发布链既有）+ `updateCaseDetail`（全量覆盖 8 列，`affected !== 1` 或异常 → `UPDATE_FAILED`「案例明细更正失败，请稍后重试」）。
- `reference-document.service.ts`：`updateDocument` 入参扩展 `ReferenceDocumentUpdateData`（标题/机型 ID/机型文字/说明/可读正文/文档类型/修改人），不改 owner/source/type/原附件列。

### S6-4 专属更正用例

- 新增 `backend/src/usecases/reference-document/update-reference-document-case.usecase.ts`（6 依赖：写服务、案例明细服务、查询服务、机型查询服务、组织上下文服务、事务运行器）：
  1. 角色决策：仅真实 SUPER_ADMIN（精确匹配，工程师拒绝）；
  2. 输入决策：补丁至少一个可更正字段；
  3. 事务内组织决策：本组织范围内读当前值（不存在/已软删/跨组织统一 NOT_FOUND）；类型门禁仅 FAULT_CASE（大小写不敏感）；
  4. 明细存在性：缺失=定式破坏，失败关闭（UPDATE_FAILED）；
  5. 合并允许字段后最终态验证（必填/RESOLVED 结果/机型互斥）；
  6. 可读正文由合并后明细重新生成；
  7. 同一事务更新主资料（含 `documentType` 保持与 `updatedByAccountId`）+ 全量覆盖明细；回读真实落库状态返回 `{id, updatedAt}`。
- `reference-document-usecases.module.ts` 注册新用例。

### S6-5 GraphQL 协议入口

- `reference-document-write.dto.ts` 新增 `UpdateReferenceDocumentCaseInput`（12 字段；class-validator 与 normalize 双层校验，双层 message 同口径）。
- `reference-document.resolver.ts` 新增 mutation `updateReferenceDocumentCase(id, input)`：`@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles(SUPER_ADMIN)` + `@ValidateInput()`，返回 `ReferenceDocumentCaseMutationResultDTO {id, updatedAt}`。
