# 复核报告响应与修复计划（20261021）

依据：[修复计划逐项复核报告](./修复计划逐项复核报告.md)。

## 结论核对

四项 P2 均已在当前代码中复现核实：

- V01 成立：`createTestAccount` 回落路径无事务，`seedTestAccounts` 用 `Promise.all` 且只在完整返回后登记；中途失败会留下未登记半账号，且一项失败时其他造数仍在途。
- V02 成立：`collectOwnedGraph` 仅在 `orgIds.length === 0` 时按账号查成员关系；owned 组织非空时，owned 账号在外部组织的成员关系直到 DELETE 才被外键拒绝。
- V03 成立：`assertSeedMembershipOwnership` 只比 id/org/account，`upsertSeedMembership` 的 SAME 分支无条件重置角色/状态/left_at。
- V04 成立：`signalLockAttempt` 只唤醒已注册 waiter、不保留到达事实；W 用例在启动竞争请求后才注册 waiter，存在丢通知窗口。

## 修复计划

1. **V01**：回落账号创建改为单事务（账号 + 密码回写 + user_info 原子提交）；`seedTestAccounts` 改用 `Promise.allSettled`，全部收敛后登记成功项并抛出首个错误。
2. **V02**：成员预检同时按 owned 组织与 owned 账号两个方向查询取并集，逐行核验两端归属；任一方向越界即预检失败、DELETE=0。
3. **V03**：成员读取补充 `member_role`/`status`/`left_at`；SAME 仅当角色、状态、left_at 与 Seed 指纹完全一致；不一致失败关闭且零写入，匹配时纯 no-op。
4. **V04**：屏障改为“先创建本轮 waiter（可先于信号）再启动竞争请求”，信号可命中已创建 waiter，不依赖注册时机；同一投稿多轮用新 waiter 隔离；补充超时回收与两种先后顺序、W06 文本+附件移除成功分支。
5. **验证**：补 V01/V02/V03/V04 反例测试；实库复跑清理 C 系列（连续两次、非空库、无 TRUNCATE）、W 系列、Seed 双跑与冲突回滚；后端 typecheck/lint/unit/build 门禁。

## 边界

不新增业务表，不改 Migration/实体，不改全局隔离级别，不在 `src/` 注入测试钩子，不执行 commit/rebase/push/PR。
