## 3. R25-01 的具体修复设计

### 3.1 根因与入口

- `backend/test/utils/e2e-scoped-cleanup.ts:499`：组织/账号可删集合为空，但保留账号命中时仍进入图收集。
- 同文件 `:538`—`:554`：`submissionConditions` 为空，却仍执行 `WHERE ${submissionConditions.join(' OR ')}`，得到 `WHERE FOR UPDATE`。
- 直接调用方：`backend/test/10-admin-document-database/admin-document-database.e2e-spec.ts` 的 beforeAll 与 afterAll；账号/业务夹具创建先于组织创建，组织建立前失败即可触发。
- 当前后果：组织链清理抛错，后续账号/业务 fixture 精确清理未执行；错误仍传播、应用仍关闭。本次不应误修 teardown 的 closeApp。

行号为审查基准；实施时按符号定位，不机械套用修改后的行号。

### 3.2 首选最小实现

在执行投稿子图查询的位置，根据 **该条查询自己的条件集合** 决定执行：没有条件则返回空结果，不执行 SQL；有条件则沿用原带参数查询。

实施时必须检查后续图收集仍会执行：**不要在 collectOwnedGraph 整体提前 return**，否则可能遗漏已有 document/revision/attachment 等资源的必要核验。保留账号指纹核验也不能被跳过。

默认只需修改 helper 与相应测试。10 组若能通过测试侧注入验证原组合收尾，就不改其业务/测试编排；只有证明现有编排本身还存在独立缺陷，才另列反例并作最小修改。

明确禁止：将 retainedAccounts 加进待删账号、改成无 WHERE 全表查询、放宽指纹/外部引用检查、吞清理错误、关闭双门禁、开启 synchronize、增加生产测试开关、重写无关测试域。
