## 3. 五项实现要求

### 3.1 N05：测试不能自行授予物理删除许可

**位置**：`backend/test/fixtures/cleanup-faults-child.e2e-spec.ts` 的 beforeAll/afterAll，及其父规格。

1. 在任何造数、故障注入之前捕获原始许可，并独立校验它恰为 `'1'`。缺失、`'0'` 或其他值拒绝；不得先创建数据再用兜底清理补救。
2. 初始化失败时 afterAll 仍可能被 Jest 调用：只做已授权且可确认的收尾，不在该分支补出许可或生成“零残留所以成功”的结论。
3. F09 临时撤销许可后，afterAll 只能恢复**已经校验的原始值**；移除无条件写入 `'1'`。原值恢复在 finally 中完成，但 finally 也不能凭空授予许可。
4. 区分“启动许可未通过”“启动已获许可、测试主动撤销”“应用初始化失败”状态，防止未完成 beforeAll 的变量默认值导致 afterAll 走错分支。
5. 仅有许可还不够：原库名、目标一致性、行级范围及事务保护照常生效。关闭资源不因许可拒绝被跳过，原错误不能被覆盖。

**验收**：缺失/0 两类启动下造数与 DELETE 均为 0、runner 非 0 且指出许可错误；原值 1 时既有 F07/F08/F09 正常运行，临时撤销会失败，安全恢复后可回收，进程原值恢复正确。不能只断言 runner 非 0。

### 3.2 N04：核对预期目标和实际清理连接

**位置**：`backend/test/utils/e2e-db-guard.ts`、`e2e-scoped-cleanup.ts` 调用位置、相关守卫/ownership/fake DataSource 测试。

1. 明确预期目标来自当前已配置 DataSource 的 database，或现有调用契约显式传入的测试目标；选定一种一致的来源并记录。不能以当前 `SELECT DATABASE()` 回填预期，不能缺失时回落到个人环境文件或随意默认库。
2. 对预期库和实际库各自核验允许名单，并要求实际等于该次预期。两库都允许也不能互相替代；预期缺失/空白应失败关闭。
3. 入口可先快速拒绝；**事务内预检与删除所用 manager/queryRunner 的实际库仍需核对**。不能只在连接池另一条连接上查询库名后，就替实际删除连接作证明。
4. 在可取得实际连接的地方保持同一会话完成必要身份核对、归属/引用预检和删除。原批次事务、顺序、空目标策略及错误传播保留。
5. 仅调整必要测试守卫及直接消费者/替身；新守卫要求预期配置时，测试 fake 必须明确提供，不能添加“fake 无配置就跳过”的运行时豁免。
6. F11 的“预期不允许”“实际不允许”“均允许但不一致”使用真正不同的输入/连接事实，不再只换两个白名单字符串。

**验收**：许可缺失、预期不允许、实际不允许、均允许但不同、预期缺失、完全一致分别验证。拒绝在首删前，目标与哨兵不变；完全一致才进入后续归属核验。保留 skip 全局清理的组合。

**真实反例**：在独立实例中准备 A/B 两个临时 E2E 库，A 为配置预期；使用单连接真实切换会话至 B，两者均明确允许，B 有合成目标。调用正式清理入口必须拒绝，B 行保持不变。只改变 Proxy 返回值可作补充，不能替代实库反例；此实验不在保留库运行。

### 3.3 N02：事实与调用方输入隔离

**位置**：`recordOwnedResource`、`updateOwnedExpectation`、`mergeOwnedResourceLedger`。

- 登记时保存独立事实快照，根对象、角色数组、payload 嵌套对象/数组均与输入隔离。
- 显式更新应从原事实和已成功写入对应的 patch 形成新快照；patch 后续变化不能修改台账。失败写入不更新预期。
- 跨台账合并同时隔离事实值。源输入或源台账后续变化，不应靠对象别名偷偷改变目标预期；如果同一资源有多个兜底台账，合法变化须显式同步或统一其明确的预期更新路径。
- 可用 Node 22 适用的克隆能力处理当前事实类型；保持 null/false/0、数组、JSON 及既有枚举语义。不用 JSON 序列化悄悄丢弃值，不使用 `any`，不引入通用状态管理框架。
- `readonly` 不能替代运行时隔离；也不需要新增防恶意直接篡改内部 Map 的权限系统。本次针对普通调用方持有的输入别名。

**验收**：登记后改原对象、改角色数组、改 payload 嵌套值；更新后改 patch；合并后改源值，均不隐式改变目标预期。数据库随这些未声明变化改变时，应首删前拒绝。只有显式受控更新能允许相应合法清理。

### 3.4 N01：补齐约定的用户资料事实

**位置**：`OwnedAccountFacts`、`verifyOwnedExpectations(account)`、账号创建工具及资料变更消费者。

1. 为已有账号事实补上必要的用户资料昵称、资料邮箱、用户资料状态；保留账号本身状态/身份与 accessGroup。命名/嵌套沿当前风格，不新增业务 Entity。
2. 区分账号 loginEmail 与 user_info.email、账号 status 与 user_state；特殊状态 fixture 的两类状态可能刻意不一致，不能简单互相推导。
3. 在受控创建阶段由已知输入/创建结果登记，按字段实际可空契约比较，不用 falsy 默认值吞掉 null/空值。不能在清理时读取当前值作为预期。
4. 同事务锁定后核对资料存在性与预期字段；账号存在但本应存在的资料已缺失，应拒绝。若确有合法不创建资料的夹具，须在创建时明确该预期，不临时把缺失解释为允许。
5. 合法昵称/邮箱/状态修改成功后显式更新预期。逐一核对实际变更这些字段的 04 用户资料、管理用户、账号设置等消费者，避免补字段后正常路径只能靠跳过检查运行。
6. 不新增全列快照，不要求匹配自动更新时间，不保存或输出密码、Token、加密密钥或不必要密文。

**验收**：nickname、user_info.email、user_state 分别独立漂移时拒绝且 DELETE=0；资料缺失拒绝；合法变化更新预期后可回收；创建缺必要事实时失败关闭。原资料编辑/特殊状态账号规格通过。

### 3.5 N03：连接不可用时保留台账和失败状态

**位置**：`backend/test/utils/owned-ledger-lifecycle.ts` 的 afterTestCleanup、cleanupRetainedForAfterAll 及 register/故障子规格调用。

| 台账/失败状态 | DataSource 状态 | 要求 |
| --- | --- | --- |
| 真正空批次且无未决失败 | undefined／未初始化／已关闭 | 可安全空操作，不执行 DELETE，不伪造“已提交清理”证据 |
| 非空批次 | undefined／未初始化／已关闭 | 记录不可确认回收的失败原因，保留全部 ID/事实，不调用 resetOwned，抛错 |
| 有未决失败 | 任意不可用状态 | 原失败及台账继续保留，不能清空失败标记或静默恢复就绪 |
| 非空批次 | 可用且清理明确提交成功 | 成功后才重置，下一用例允许继续 |
| 任意待清批次 | 清理拒绝／回滚／结果未知 | 保留状态，下一用例失败关闭，afterAll 可诊断并按原安全入口恢复 |

将获取/检查连接的失败也纳入生命周期失败记录，防止仅抛错但不置失败状态、随后下一用例仍继续。afterAll 不可用时不能静默声称已回收，但应用/连接关闭和环境恢复仍执行；新增错误不得掩盖原错误。

**验收**：真实创建目标后关闭清理 DataSource，再调用实际生命周期工具；台账不变、reset=0、失败状态可见、数据库目标仍在，下一用例拒绝。随后明确重新取得合法连接并通过安全清理后，才允许标记回收。空批次的三种不可用状态分别测试。

## 5. 两项独立补证

### D1：真实初始化失败到真实收尾

新增或扩展受控 Jest 子夹具，beforeAll 先通过启动许可及库守卫，再成功创建并登记一个资源；随后在第二个真实创建事务的关键写入点注错，直接使 beforeAll 失败。

由实际 Jest 调度 afterAll，验证：测试体未运行；首个已提交资源一直在台账中直至明确清理提交；第二个事务回滚无半账号；原初始化错误、清理及关闭结果可分辨；进程非 0。父进程用独立连接再核对本轮资源零残留及非本轮哨兵不变。

该夹具不加入普通 core 的独立失败列表，仅由父规格显式启动。只在 it 内调用模拟 failingBeforeAll 函数，或捕获造数 reject 后继续，均不能替代此证据。

### D2：事务负对照准确命中快照断言

现有 NC4 的失败首先是错误主因匹配变化，不能据此声称快照断言已被验证。调整测试侧故障注入位置，使正常事务与临时无事务变体**都经过同一个精确 SQL 注错点**：

1. 两者均确认前序 DELETE 已执行，第 N 次 DELETE 抛出同一个预期错误；计数、主因及 finalize/close 路径保持一致。
2. 正常候选事务回滚，账号/资料/成员等目标与事前快照一致。
3. 临时变体仅绕过整批事务，不移除注错；错误主因断言先通过，再由“前序删除未恢复”的快照断言使测试红。
4. 恢复正常源码后，同一规格绿。变体使用独占实例/数据域，残留与红测保存明确，不能手工清空后把正常复跑当作原子性证据。

不在生产添加故障开关，不保留 mutation 源码到候选。已有真实回滚实现无需重写。
