## 3. 发现的问题

### Q01 [P1，合入前修复] 新 H 父规格仍按固定名字删除非本轮数据库

1. **位置**：`backend/test/utils/e2e-probe-lifecycle.e2e-spec.ts:106`—113，尤其第 111 行原始 DROP；启动调用第 169 行；最终调用第 175 行；第 219—220、244—245、260—261、297—298、312—313、405—406 行还有“存在就 RESET”的调用。
2. **最小触发**：主 E2E 库合法，执行者给了清理许可，但在启动 H 规格前，`lithography_e2e_probe` 已存在且由其他运行创建。许可不是对这个既有库的所有权证明。
3. **当前行为**：beforeAll 的 PRECHECK 无条件调用该函数；函数仅查库存在，不核对创建事实/归属便 DROP。`foreignProbeOwned` 只在部分用例影响是否调用，不在删除函数中校验；PRECHECK、FINAL 和多个 RESET 无此限制。
4. **期望行为**：已有同名库应碰撞拒绝并保持原样，beforeAll/afterAll 不能接管。只有父规格自己明确创建的夹具库，或得到明确本轮创建成功证据的子进程资源，才能精确回收。未知资源不能靠存在性或固定名认领。
5. **依据**：计划 K2/K6/K7、P1/P3/P4，以及专项 H01/H09；新增父测试的准备和收尾必须继承同样的所有权要求。此要求已在计划中，不是本轮新增验收标准。
6. **实际影响**：正式 core 会执行这个规格。已有其他运行的探针库及数据可能被整库删除，所有 9 条断言依然绿色。
7. **本轮实测**：只在本轮新建独立实例 `127.0.0.1:27766` 预置合成库及 `keep_nonfixture` 表、1 行记录。正式 runner 运行 H 文件：日志出现 `PARENT_CLEANUP_PRECHECK=done`；**9 passed、exit 0**。之后原表不存在，最终探针库也不存在。实例 `Com_drop_db` 从 0 到 7，其中包含正常测试夹具回收，不能将 7 全部解释为误删；启动 PRECHECK 与原表消失已足以证明问题。
8. **现有测试漏检原因**：H01 的 `foreign_marker` 是在 PRECHECK 删完原库之后才创建的。H01 只验证子 G04 保留这份新夹具；未从 H 规格外预置不归父规格的库，也未断言父生命周期不接管。现有负对照只恢复子 G04 的错误，无法检验父层同类错误。
9. **最小修复方向**：去掉 PRECHECK/RESET/FINAL 的存在即删除语义；父夹具 CREATE 明确成功后立即记录所有权，失败不认领；所有父层回收统一经过该所有权判定。H06 的额外卫生清理须持有与具体子运行/目标绑定的明确创建证据，不能仅用固定名或“本来预期是本轮”证明。不需要新增生产表、通用锁框架或扩大清理范围。
10. **必须补证**：从规格外真实预置异主库，运行正式 H 父规格，要求安全拒绝、前后 schema/行快照不变、零 DROP，真实 afterAll 不删除它；覆盖初始化拒绝、FINAL、RESET 的同一门禁、成功创建后失败及本轮正常回收。反向临时恢复父 PRECHECK 后，这条保护断言应失败。修复后再对最终候选执行计划必要回归。**归属：当前修复包阻塞。**

这是“同一所有权根因迁移到了新测试父层”，不是原业务出现新的数据库需求，也不是必须重写原 G04 helper。

1. **位置**：`docs/database/PR0-B审查core清理安全修复计划-20261026/core清理安全完整收敛修复执行回执-20261027.md:123`；关联该文件第 6 节的负对照描述。
