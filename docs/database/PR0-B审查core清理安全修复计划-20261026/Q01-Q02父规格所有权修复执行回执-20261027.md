## 3. 修复对应

### 3.1 Q01（P1，父规格所有权）

根因：H 父规格 `dropProbeByParent` 只查库存在，PRECHECK/RESET/FINAL 均按固定名 DROP，许可与库存在性被误当成所有权。

修复对应：

- **K2（固定名不是归属证据）**：删除父层“存在即 DROP”函数与 `foreignProbeOwned` 布尔；PRECHECK/RESET 统一 `assertProbeDatabaseAbsentOrOwned`，无归属即碰撞拒绝。
- **K2/K7（明确资源与目标）**：父夹具、子交接、外层夹具均记录 `runId/target/instance`；`dropOwnedProbeDatabase` 与台账在 DROP 前校验 scope，不符直接 throw 且未发 SQL。
- **K6（子进程明确创建事实）**：G04 仅在 CREATE 明确成功分支输出 `G04_CREATE_CREDENTIAL=`；父侧只接受唯一、合法、全等的结构化凭据；`E2E_G04_RUN_ID` 未设置时 G04 不输出凭据（脱离具体运行不产生可删授权）。
- **K8（隔离负对照）**：见 §5，全部在临时源码副本执行。
