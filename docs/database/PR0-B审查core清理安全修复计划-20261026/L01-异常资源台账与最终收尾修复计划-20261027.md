## 3. 要接入真实收尾的资源与最小实现

### 3.1 覆盖表

| 资源/入口 | 当前缺口 | 必须达到的行为 |
| --- | --- | --- |
| H 的父夹具 `parentLedger` | 已有正常保护 | 保留现有路径，纳入同一收尾视图，不能因修子账本降低父账本保护 |
| H06 `handoffLedger` | 有效记录只存在用例局部 | 凭据验证且确认子结束后，立即把子运行账本交给规格可访问的拥有者状态；后续断言/父回收失败不丢失 |
| J 主 `outerLedger` | 只覆盖主 probe | 保留并与所有辅助资源统一收尾，不用它冒充 AUX 的拥有者 |
| J04/J08 `createRawForeignFixture` | CREATE 后没有外层拥有者登记；建表/断言失败跳过末尾 DROP | 原子 CREATE 明确成功后立即登记到驱动器自己的账本，再建 marker/插行。正常及异常收尾都经过该拥有者入口 |
| J03/J04/J05/J06/J08 的局部辅助 ledger | 用例提前退出后 afterAll 访问不到 | 这些真实拥有资源的账本在取得归属时进入规格可达状态；纯空账本/纯替身不获得删除资格 |
| 对应正常末尾清理和 FINAL | 两条路径可能分裂或重复授权 | 共用既有受保护回收语义；成功消费后 FINAL 不再 DROP；失败记录保留给后续收尾/诊断 |

### 3.2 推荐的最小结构

可以使用规格作用域内一个小型账本集合及窄的登记/收尾函数；或者使用等价的已拥有资源作用域封装。**不需要生产表、通用资源框架或新的权限体系。**

- 集合登记的是带 run/target/instance 的已有拥有者账本，不能只保存一个库名字符串或 `true`。
- 创建资源的操作在 CREATE 明确成功后立即保存账本/记录，中间不得插入可能抛错的断言、建表或其他异步工作。
- H06 在严格凭据验证并满足既有子结束条件后登记；错目标、错实例、缺失/损坏凭据和未确认结束仍不认领。
- “相对 SUT 异主”的 fixture 仍属于驱动器本轮创建资源：拥有者账本归驱动器，**不能写入要保持为空、用于验证 SUT 拒绝接管的账本**。
- 成功消费后的空账本可移除或保留为空；不能再次作为同名库的删除授权。失败账本不得因用例结束、集合重建或 beforeEach 重置而丢失。
- 同一资源不登记多个活跃删除授权；不同运行/目标不能合并成一个布尔状态。恢复阶段发生冲突时拒绝而非接管。

## 4. 真实收尾的成功、失败与未知规则

1. 可在 afterEach 精确处理本用例已知资源，再由 afterAll 处理仍未决记录；也可在严格隔离并阻止脏状态继续造数的前提下由 afterAll 统一处理。选择后必须覆盖实际代码，不只提供一个正确 helper 却不在钩子中调用。
2. 清理遍历应逐资源捕获错误。一个资源失败不跳过其他已知本轮资源；随后环境恢复和 app/连接关闭也独立尝试。保留测试/初始化主错误与清理/关闭错误，不吞成绿色。
3. 所有正常末尾清理、afterEach、afterAll 共用归属与消费规则，不再增加 `DROP DATABASE 固定名`、存在即删或先清场重跑的旁路。
4. **明确未发送的临时失败**：保留记录，允许真实 FINAL 对同一已证实属于本轮的目标做有界收尾；测试应验证一次用例回收失败后 FINAL 仍看得到并可安全回收，不要求无限重试。
5. **真实结果未知或连接不可用**：不能为零残留盲目重试或另开高权限连接。保留运行/实例/目标、创建或交接来源、失败阶段及是否尝试回收，非零退出，仍关闭其他资源。最终状态必须明确是“未决”，不能写 skipped-not-owned 或已释放。
6. 启动拒绝、碰撞、CREATE 未知且没有成功事实、无效交接：不建立归属记录，不 DROP。因这些路径确无记录时，skipped-not-owned 仍是正确结果。
7. 已明确 DROP 成功才消费记录；成功回收后的 FINAL 不重复操作。不能为了让新的回归通过，把“任何情况下都自动删掉”当完成标准。
8. 保留非夹具库的碰撞拒绝、许可和预期/实际目标保护。只在获准新建独占可丢弃实例运行；不把“有本轮记录”外推为允许操作任意真实实例。
