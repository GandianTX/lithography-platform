## 3. 资源生命周期表（V1）

集合语义：`ownedLedgers.add(label, ledger)` 只登记**已有** run/target/instance 台账；`settle` 对每条记录单独 `has()` → 无记录 `skipped`、DROP 成功 `dropped` 并消费、异常 `failed` 且保留记录。

| 资源/入口 | 拥有者记录 | 登记时点 | 规格生命周期可达位置 | 正常消费 | 异常/未知状态 | 最终访问方 |
| --- | --- | --- | --- | --- | --- | --- |
| H 父夹具（`lithography_e2e_probe`，H 运行） | `parentLedger` | `beforeAll` 建立并 `add('parent')`；H01 CREATE 明确成功后立即 `record` | 模块级 `ownedLedgers` | H01 末尾 `dropParentOwned('H01')` | 记录保留；FINAL 逐资源 `dropped`/`failed` | H `afterAll` → `settle` |
| H06 子交接（子运行 G04 的 `lithography_e2e_probe`） | `handoffLedger`（子 run/target/instance） | 严格凭据解析 + 确认子结束 + `add('h06-handoff')` + `record`，在同一步内完成 | 模块级 `ownedLedgers` | H06 父侧 DROP 成功即消费 | 父侧 DROP 未发送/失败：记录保留，FINAL 有界重试或 `failed` 保留 | H `afterAll` → `settle` |
| H03/H04/H05/H09 的 G04 探针 | G04 子进程自己的台账 | G04 子进程内 CREATE 成功后 | 子进程；父进程不接管 | 子进程 `afterAll` | 父进程只核验日志/库状态，不建立跨进程删除授权 | 子进程；父进程独立查库 |
| J 主 probe（`lithography_e2e_probe`，J 运行） | `outerLedger` | `beforeAll` `add('main')`；J01 CREATE 成功后立即 `record` | 模块级 `ownedLedgers` | J01 末尾 `dropLedgerOwnedProbe` | 记录保留；FINAL `settle` | J `afterAll` |
| J03 辅助库 | `j03` | 真实 CREATE 成功后立即 `record`；异常退出前完成登记 | 模块级 `ownedLedgers` | J03 末尾窄回收 | L-A 注入：记录保留，FINAL 回收 | J `afterAll` |
| J04/J08 原始夹具（`outer_keep`） | 驱动器自己的 `j04-raw` / `j08-raw` | `createRawForeignFixture` 内 CREATE 成功后**立即** `record`，再建 marker/插行 | 模块级 `ownedLedgers` | 正常末尾 `dropRawFixture` | L-B 注入/断言失败：记录保留，FINAL 回收 | J `afterAll` |
| J04 `j04-owned` / `j04-failing` | 同名台账 | CREATE 成功后 `record` | 模块级 `ownedLedgers` | 成功 DROP 即消费 | 失败保留；同用例末尾真实重试（有界） | J 用例末尾 + `afterAll` |
| J05 `j05-invalid` / `j05-timeout` | 同名台账 | 只在有效凭据统计成功时登记 | 模块级 `ownedLedgers` | 有效路径 DROP 成功即消费 | 无效/超时：空账本不解析数据源、不 DROP | J `afterAll`（空跳过） |
| J06 辅助库 | `j06`，或 L-D 专用 `j-inject-final` | CREATE 成功后立即 `record` | 模块级 `ownedLedgers` | 末尾真实重试成功后消费 | L-D：拒绝桩 → `failed`、记录与库保留、`OUTER_FINAL=partial` | J `afterAll`；预期残留由拥有者按凭据另行处理 |

## 4. 实现内容（V2/V3）

新增/修改均在测试 helper/规格内，无生产代码：

1. `backend/test/utils/probe-database-lifecycle.ts`
   - `ProbeOwnershipRegistry`：按 label 登记账本；拒绝重复/标签冲突；`settle()` 逐资源独立尝试，无记录 `skipped`、成功 `dropped` 并消费、异常 `failed` 保留并聚合。
   - `probeSettlementState()`：无失败且无回收 → `skipped-not-owned`；有回收无失败 → `settled`；任一失败 → `partial`（不再对已拥有未决资源伪报无归属）。
   - `describeProbeSettleResult()`：单资源日志含失败单行诊断。
   - `throwProbeSettlementError()`：失败聚合抛出，`cause` 保留首个失败。
2. H 规格：`ownedLedgers` 模块级集合；`parentLedger` 与 `h06-handoff` 均 `add`；`afterAll` 逐资源输出 `PARENT_FINAL_<label>=...`、`PARENT_CLEANUP_FINAL=settled|partial|skipped-not-owned`，失败聚合；`E2E_H06_DROP=once-fail` 让父侧第一次 DROP **发送前**失败（不发出 SQL），用例按原错误失败，真实 FINAL 重试回收。
3. J 规格：`ledgerFor()` 一律把 ledger 登记进 `ownedLedgers`；`createRawForeignFixture()` 改为“驱动器自己的账本：原子 CREATE 成功 → 立即 `record` → 再建 `outer_keep`/插行”，异常不再依赖末尾清理；`dropRawFixture(ledger, reason)` 走既有窄回收；`afterAll` 逐资源 `OUTER_FINAL_<label>=...`、`OUTER_FINAL=...`，`E2E_J_FINAL_DROP=unknown` 只对专用标签 `j-inject-final` 使用拒绝桩。
4. 新增 `e2e-probe-lifecycle-faults.e2e-spec.ts`（L-A—L-G 外层验收驱动，已加入 core 列表）。故意失败的子规格不直接进 core；外层驱动器以正式 runner `--file ... -t <精确模式>` 启动它们，并独立查库核验。
5. `test/jest-e2e.js` core 列表由 46 → **47** 个规格。

直接消费者核对（`probe-database-lifecycle`）：`e2e-db-target-consistency`、`e2e-probe-lifecycle`、`e2e-probe-lifecycle-outer`、`e2e-probe-lifecycle-faults`；签名扩展保持向后兼容（可选 `scope`、可选 `expectedScope`）。
