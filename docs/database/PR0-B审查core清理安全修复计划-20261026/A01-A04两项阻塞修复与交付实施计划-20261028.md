## 4. A01：显式配置足以独立运行

### 4.1 原因、真实入口与最小修复

真实链：配置文件 → `loadConfig`/校验 → `buildChildEnv` 和 `writeSanitizedDotenv` → 正式 runner/setup → Nest 配置消费者。

当前启动器的 `REQUIRED_KEYS`、净化 dotenv 和子 env 遗漏 `PAGINATION_HMAC_SECRET`、`FIELD_ENCRYPTION_KEY`、`FIELD_ENCRYPTION_IV`；传入的 `AI_PROVIDER_MODE=mock` 同样未传递。直接消费者为：

- `backend/src/infrastructure/config/config.module.ts`：分页必需密钥、运行配置验证和 AI 模式。
- `backend/src/infrastructure/field-encryption/field-encryption.service.ts`：必需 key/IV。
- runner/setup/teardown 的配置加载路径，以及实际最小 Nest 规格 `backend/test/00-app/00-app.e2e-spec.ts`。

当前机器可从其他本地 env 补值，故已有绿色 core 未证明独立运行能力。最小修复必须：

1. 核对本期真实消费者，列出小型必要运行键；至少覆盖上述三项和明确的 mock 模式。不遍历支持所有未来可选能力。
2. 必需值缺失/空白在连接或 spawn 前准确拒绝；加密参数满足现有消费者的格式/长度规则，不修改生产校验、不改变加密算法。
3. 三项值按显式验收配置传入实际子环境和必要净化文件，保持同源，不从父 shell 补缺。当前验收明确使用 `AI_PROVIDER_MODE=mock`，不允许因此启用 remote。
4. 保留已有 JWT、DB/Redis 绑定、清理授权隔离。净化文件仍不包含会重新注入的 E2E 清理许可。
5. 不用 `...process.env` 或透传全部配置解决；合成密钥只在本地临时配置中生成，不打印、不提交真实秘密。沿用现有私有文件约束，不建立新配置框架。

## 5. A04：未确认子运行结束，不取得删除资格

### 5.1 原因、真实入口与最小修复

真实链：`runJ06` 的 `spawnSync` 结果 → `receiveAndOptionallyDrop` → 凭据解析 → 目标核验 → registry/ledger → `dropLedgerOwnedProbe` → afterAll FINAL。

当前仅检查 `child.status === 0`，所以 `status=null` 携带匹配创建凭据仍会进入登记/删除。凭据证明创建归属，不代替子运行结束确认。既有正常故障用例只有预期非零结束，故没有命中该分支。

必须在凭据接收和任何认领/登记/删除前拒绝未确认结束结果：null、信号终止、超时或启动错误等实际可达的非正常结束事实。保留必要的错误/信号诊断；若现有 `ChildRun` 丢失辨别所必需的 `spawnSync.error`，只在此窄边界补充传递。不能只靠输出中有成功标记判断结束。

正常明确结束的非零结果是 J06 的预期行为，仍须凭唯一匹配的 run/target/instance 凭据交接；零退出继续按既有预期拒绝。保留即时 registry 登记、失败留账、真实 FINAL 可达、成功消费以及恢复/关闭独立执行。

不增加通用进程管理框架、不等待 15 分钟制造真实超时、不手工 DROP 未认领目标。拒绝未确认交接时保留诊断，不伪报已清理或零残留；此时未登记目标也不能被本规格 FINAL 擅自认领。

### 5.2 必须验证的最小反例

| 输入/阶段 | 必须行为 |
| --- | --- |
| status=null、signal=null，带唯一正确凭据 | 接收函数拒绝；registry.add、ledger.record、DROP 均零调用 |
| 信号终止或超时/启动失败结果，仍有正确凭据 | 同样拒绝；诊断可辨，不凭凭据执行回收 |
| 测试边界构造非空 signal 与数值 status 的不一致结果 | 拒绝，不因 status 非零放行 |
| status=0 | 继续拒绝，不登记/删除 |
| 明确正常结束、非零、匹配凭据且目标存在 | 允许交接；保留正常消费及 FINAL 路径 |
| 正常非零但错 run/target/instance 或无凭据 | 保持既有拒绝，不放宽归属规则；复用已有覆盖 |

测试必须调用**实际接收实现**，只替换子结果/精确外部边界；不要复制一份正确判断算法当被测对象。建议复用现有故障规格测试方式；如需提取窄函数用于测试，保持语义局部，不另造所有权/清理框架。

状态拒绝允许精确故障注入，不必真实制造失控子进程；正常非零交接、V-LD/V-PENDING 的 FINAL 则复用现有真实链。未知结果不等于 DDL 能事务回滚，本轮也不修改 DDL 模型。
