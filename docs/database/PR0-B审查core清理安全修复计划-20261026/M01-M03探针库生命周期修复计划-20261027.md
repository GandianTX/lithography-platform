## 3. 最小实施方案

### 3.1 M02：许可前置，不由测试自行授予

1. 在 beforeAll 的应用初始化、探针库创建/删除和造数之前捕获原始 `E2E_ALLOW_PHYSICAL_CLEANUP`、`E2E_ALLOWED_DB_NAMES`，独立校验启动许可恰为 `'1'`。
2. 原值缺失、`'0'` 或其他非法值时拒绝；afterAll 可能仍执行，但不能补授权、做 DDL 或造数。仍须释放已经分配的资源。
3. 移除 beforeAll 和两个 it 中无条件设置许可 `'1'` 的语句。G04/G04b 无需主动撤销许可，不必为它们增加许可切换状态机；如确有受控故障需要，只能恢复先前已验证的原值。
4. 主库预期/实际与白名单检查保留。探针名字仅允许确定的测试命名，不接受未经校验的任意库名拼入 SQL。
5. 局部名单调整必须以已授权准备、明确本轮创建所有权为前提，只包含本次需要的目标，不能靠扩大名单取得删除既有库的资格。所有结束路径恢复捕获原值，包括 undefined 与 `'0'` 的原始区别。
6. DDL 与 DML 同样受启动授权约束；`E2E_SKIP_DB_CLEANUP`、MySQL 账号有 CREATE/DROP 权限、代码运行在 test 目录，都不能替代执行者许可。

### 3.2 M01：固定名碰撞拒绝，只销毁本轮创建的库

推荐本轮继续使用 `lithography_e2e_probe`，以减少 G04/G04b 接口和断言改动，但必须改变创建语义：

- **删除 beforeAll 的 `DROP DATABASE IF EXISTS`。** 使用不带 `IF NOT EXISTS` 的 CREATE，让 MySQL 原子地拒绝已有库。可预查存在性用于友好诊断，但不能仅靠“先查不存在”判断归属。
- CREATE 返回明确成功之后，才登记 `probeCreatedByThisRun=true` 及固定目标/实例事实；只有这条成功路径可获得销毁资格。初始化、克隆结构、连接和造数成功与否不改变该归属来源。
- CREATE 以“已存在”拒绝时，afterAll 不得 DROP；既有库的表、数据、文件引用等保持不变，不按表结构相似或名字像测试库接管。
- CREATE 超时/连接断开导致结果未知时，不将“随后能查到库”认作本轮所有，不自动 DROP；保留精确目标和未知阶段的脱敏诊断。不能为凑零残留删除无法证明归属的库。
- CREATE 已确认成功、但后续第 N 张表克隆/shifted 初始化/造数失败时，可以按本轮所有权及已验证许可收回该库，仍须关闭其他资源。
- 销毁明确成功后才标记已回收；DROP 失败/结果未知时保留失败和目标诊断，不能伪造已删除。
- 名称碰撞与并发竞争下，只允许 CREATE 成功方销毁自己的库；不得让失败方 afterAll 删除另一方的库。固定名方案可以失败关闭，不要求自动接管残留或新增锁平台。

若改用唯一临时库名，仍需同样的创建确认、命名校验、所有权和异常规则；同时更新 G04/G04b 目标、名单、错误断言和父规格检查。不要保留“随机名所以无需归属”的豁免。

### 3.3 M03：每一步收尾失败都不能阻止其他关闭

在现有 `runE2eTeardown` 或同等窄实现上编排，不把多个释放动作塞进一个会首错中断的 callback：

- 本轮拥有的探针清理失败，仍尝试 shifted 连接销毁、环境恢复和 app.close。
- shifted.destroy 失败不能阻止 app.close；app.close 失败也不能丢失此前数据库错误。
- 只有主连接可用、目标明确、启动已授权且本轮确实创建，才允许执行探针清理；否则保留诊断并跳过无资格的 DROP，不能另开高权限入口补删。
- 根据实际连接依赖安排顺序：执行 DROP 的主连接应在 DROP 尝试之后关闭；shifted 连接应在销毁探针前尽力释放。各步骤错误分别记录，不能因前一步失败让整段后续步骤跳过。
- 在应用/连接创建后立即保存可释放引用；初始化部分失败时也能关闭已经分配的资源。未创建、碰撞拒绝、许可拒绝等路径不猜测存在可删资源。
- 最初初始化/测试/清理失败可辨；后续 DROP/恢复/关闭失败不得覆盖主因，不能只 console.warn 后绿色结束。
- 环境恢复和资源关闭均支持异步并被 await；正常路径不重复关闭已经确认释放的同一资源。

| 用例 | 对应项 | 最小场景 | 必须断言 |
| --- | --- | --- | --- |
| H01 同名异主保留 | M01 | 规格开始前，在独占实例预放同名库、表及非本轮合成记录 | SUT 拒绝，不 DROP、不造数；已有 schema/数据快照不变。CREATE 可以碰撞失败，但不能覆盖或接管 |
| H02 缺许可/0 | M02 | 真实子进程启动分别删除许可键、设为 0；dotenv 不补该键 | 造数及 CREATE/DROP/INSERT/DELETE 均为 0；进程非 0，原因准确；afterAll 不补许可；资源正确释放 |
| H03 正常获许可 | M01/M02 | 启动原值 1、探针库不存在 | 创建成功才登记归属；G04/G04b 仍证明预期/实际不一致拒绝且探针行保留；最终仅本轮库被收回，配置恢复 |
| H04 创建前/碰撞失败 | M01/M03 | CREATE 前失败、CREATE 明确已存在或权限拒绝 | 无本轮所有权，不执行兜底 DROP；已分配 app/连接仍尝试关闭，主因保留 |
| H05 创建后失败 | M01/M03 | CREATE 成功后，克隆表/shifted 初始化/造数处失败 | 本轮库有明确回收资格，按许可精确收尾；非本轮库不变，全部资源释放 |
| H06 创建/销毁结果未知 | M01 | 在精确调用点模拟服务端可能已执行但响应未知 | 不凭现查结果认领/删除；保留目标、阶段和未决状态，不假称零残留或销毁成功 |
| H07 单点收尾异常 | M03 | destroy、DROP、环境恢复、app.close 各自失败 | 其他释放步骤仍被尝试，次数和顺序正确；错误传播，原值恢复能执行则执行 |
| H08 多重异常 | M03 | 初始化/清理主因叠加 DROP 与关闭错误 | 主因及后续错误均可辨；测试非 0，不因最后一个异常覆盖先前错误 |
| H09 重复/竞争 | M01 | 本轮清理后重跑；另一运行已占用固定名 | 正常重复可运行；碰撞方拒绝且不删除成功方的库；未确认清理时不自动强删重试 |

关键证据要求：

1. **真实全生命周期**：H01/H02/H03 至少通过真实父/子进程运行准备→it/初始化拒绝→afterAll，并由父进程独立核对库/表/行。子进程故意失败不应被普通 core 无条件收录。
2. **覆盖 DDL**：不能只比较 Com_delete。核对 CREATE/DROP 等必要语句/成功事实及异主库快照；实例级计数只在独占、无并行干扰的环境作补充。
3. **错误替身边界**：对精确 CREATE/DROP/destroy 调用点注错可证明分支；不要 mock 掉整个收尾器再声称实际关闭通过。真实错误与测试注错分别记录。
4. **未知不是失败后可随便清空**：H06 的未知残留是需要诊断的预期边界，不要求被测实现自动删掉。若测试父进程有额外明确创建证据，后续处理须单独记录，不能冒充 SUT 自身安全回收结果。
5. **权限不足失败关闭**：测试账号缺 CREATE/DROP 权限时明确报告缺口并关闭资源，不通过自动扩大授权、切换真实库或隐藏 skip 补绿色。

最小敏感性验证仅在临时源码副本进行：恢复“先 DROP”应使 H01 非夹具保留断言失败；恢复自授许可应使 H02 零副作用断言失败；恢复首错中断收尾应使 H07/H08 的关闭断言失败。还原后同样断言通过，不把任何故障开关带入候选。
