## 2. 修复范围

1. **共享清理执行器** `backend/test/utils/e2e-scoped-cleanup.ts`
   - 新增编排级资源四类：`thirdPartyAuth`、`verificationRecord`、`repairRequest`、`engineerResponse`；
   - 残留接管只认自然键 + 逐字段指纹，字段漂移一律 `conflict`（零删除）；
   - 已在**本轮由创建证据登记真实 ID** 的资源跳过指纹接管（受控测试可能合法修改角色/状态等字段；不得读取当前值反推预期值）；
   - 引用闭包 plan-aware：集合外验证记录/维修申请/工程师回复引用本轮账号时**首删前**冲突；`ai_conversation` / `ai_report` 按账号或申请外部引用冲突；
   - 删除顺序固定为：`engineer_response → repair_request → base_verification_record → base_third_party_auth → base_user_info → base_user_account → equipment_model`，全部在单事务内先预检后逐 ID 删除；
   - 双门禁 `E2E_ALLOW_PHYSICAL_CLEANUP=1` + 库名白名单互不替代，且在读取实际库名/开启事务/第一条 DELETE 之前拒绝。
2. **删除危险导出** `cleanupTestAccounts`（原实现无条件整表删除 `organization_membership` / `base_user_info` / `base_user_account`，并吞掉错误）；`test-accounts.ts` 改为只导出 `buildTestAccountResidue` 与（可选）ownership 账本登记。
3. **迁移直接消费者 12 个**（9 core + 3 外围），全部改为“真实 ID 账本 + 双门禁 + 残留指纹 + `runE2eTeardown` 错误保真”。
4. **额外发现并修复第 13 个破坏路径**：`backend/test/02-register/register.e2e-spec.ts` 的 `afterAll` 仍在整表删除 `base_user_info` / `base_user_account`，且错误被 `console.error` 吞掉。该缺陷在 C11 首轮完整 core 中被实测命中（见 §4.1），已改为登记 `register` 返回的真实 `accountId`、按 ID 精确回收，并移除吞错。
5. **反例补齐** `backend/test/utils/e2e-scoped-cleanup.e2e-spec.ts` 新增 7 条 R02 反例（删除顺序、集合外引用、外部参与人、字段漂移等）。
