### 4.2 必须成立的状态及规则

采用现有工具可表达的最小状态，不要求通用资源管理框架：

`未拥有 → CREATE 明确成功/有效子交接 → 本轮已拥有 → DROP 明确成功 → 已释放`。

旁路状态是碰撞拒绝、创建失败/未知、销毁失败/未知。失败/未知不能跳转成“本轮已拥有”或“已释放”。

- 记录至少绑定实际操作的实例/连接上下文、已验证目标名、创建来源、具体本轮运行及未决状态；单独 `foreignProbeOwned=true` 或 `createdByThisRun=true` 不足以证明任意传入名字都可删。
- 回收前核对原始有效许可、当前目标环境和本轮记录；不得从未知对象或日志字符串直接拼 SQL。限定 probe 名称/命名规则及目标范围，复用已有校验。
- 启动许可未通过、应用初始化失败、CREATE 碰撞时没有资源归属，FINAL 不得执行破坏性查询；可关闭已经分配的 app/连接。
- CREATE 明确成功后立即保存归属，中间不插入其他异步操作。建表或插 marker 失败不抹掉成功 CREATE 事实。
- 删除失败、超时/结果未知、残留诊断失败时保留目标与创建证据，退出非零；不能清空记录再继续下个用例。
- DROP 确认成功后消费该资源记录，避免 FINAL 重复删除后来出现在同名位置的其他资源。已消费记录不能再次授权 DROP。
- 后续无归属的同名库一律拒绝；不能靠查表结构/marker 相似、名字相同、目录位于 test 判断属于本轮。
- 运行环境必须是新建独占可丢弃实例。对非受控操作者在 CREATE/DROP 间替换整个数据库的恶意并发不建立新锁平台；本轮通过独占环境前提及碰撞失败关闭控制边界，不夸称可抵御任意外部 DDL。

## 5. H06 的具体交接方案

推荐最小实现：**子创建成功时发送结构化创建凭据，父按具体运行登记；不是看到库存在就认领。** 无须生产表、通用 IPC 平台或新增权限身份。

1. 父为每次 `runG04Child` 生成运行标识，并明确指定允许的 probe 目标。父的原始许可必须先验证，不能把无许可启动升级成许可 1；缺失/0 的子场景只用于验证拒绝。
2. 子验证配置与目标，实际 CREATE 明确成功后，立即生成专用结构化凭据，至少带本次运行标识、确定目标、明确创建成功事件与实例范围；该事件只在 CREATE 成功分支发出。随后 clone-failure/drop-unknown 可继续注错。
3. 可以通过专用 stdout JSON 事件或已有合适的窄进程通道传递；普通 `G04_OWNERSHIP=acquired` 文本仍可用于可读日志，但不能单独作为任何目标的删除授权。
4. 父解析后核对发起的具体子进程、运行标识、预先允许的目标和实际实例上下文。零条、损坏、重复冲突、错运行、错目标或无法确定创建结果时均不登记、不 DROP，保留诊断并停止依赖该状态的后续测试。
5. 不能凭子进程退出 0/非 0 决定所有权：CREATE 成功后收尾失败可能退出非 0，但有有效凭据；启动拒绝/CREATE 未知也可能非 0，却没有有效凭据。
6. H06 的注错语义须明确：当前替身是“在 DROP 调用点拒绝而未发送 SQL”，子不得伪报删除。父持有有效本轮创建凭据、确认相关子进程已结束且连接释放后，才可进行额外受控回收；在回执中单列“子保留未知/失败，父侧额外卫生回收”，不能把父成功写成 SUT 成功。
7. 若子进程超时仍可能存活，先停止该受控子进程及其相关运行，不在它可能继续写库时抢先 DROP。无法确认终止或没有足够归属证据时，保留未决、失败关闭，不自动接管。
8. 父清理成功后消费交接记录。若子已明确成功清理，父记录为已释放，不再次 DROP。单凭“库现在不存在”不能反推 CREATE 成功或将其他失败伪报为成功。

如果执行者有更简单且满足同等证据与失败规则的实现，可采用并说明映射；不得以“只在测试里使用”省略归属核验。不要为了处理未知结果，另开无守卫高权限连接强删。
