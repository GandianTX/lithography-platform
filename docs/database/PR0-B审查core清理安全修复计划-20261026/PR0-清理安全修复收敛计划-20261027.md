## 5. 代码修复与同族封闭

### 5.1 已确认缺陷：只补缺口，不换框架

文件 `backend/test/utils/e2e-probe-lifecycle-faults.e2e-spec.ts`，当前 L-D 第 336—353 行：凭据已严格校验，但 `cleanupLedger` 直接创建为局部对象，没有 add；发送前失败后真实 FINAL 的集合为空。

最小改法：在首次可能失败的回收及后续断言之前，用既有 `ownedLedgers.add(稳定唯一标签, createProbeRunLedger(已校验的子运行 scope))` 建立可达记录，再 `record()`。保留子 run/target/instance，不改为父运行身份。正常成功后由原 helper 消费，异常时原 afterAll 能访问；无须重写 registry 或自动把所有空账本注册到全局。

现有测试漏检原因：L-D 只让子 J 的 FINAL 失败，却假定 L-D 自己的拥有者回收会成功；L-E/L-F 只能验证已登记集合。影响是本轮故障库残留与下次碰撞拒绝，不是再次误删外部库。

新增一个可交接的窄 Node 验收启动器，例如 `backend/test/run-pr0-acceptance.js`，复用标准 `test/run-e2e-group.js`，不复制 runner/断言。最终文件名可等价调整，但应成为本轮定向/全量/负对照和 B 清单的**必用入口**，而非旁边放一个可选检查脚本。

强制行为：

1. 必须显式提供配置路径及本轮期望目标/服务归属记录；文件不存在、关键配置缺失/非法立即非零。用配置解析器读取本地配置，不执行任意 shell source，不回落仓库默认 `.env.e2e` 或默认端口。
2. 配置明确列出 MySQL host/port/user/database、密码字段（可显式空）、Redis host/port/db/认证/TLS 与运行所需值。秘密只在本地配置/进程中，不打印或提交。
3. 原始执行许可必须显式有效；启动器不因缺失而自行赋予物理清理许可。固定本轮 `DB_SYNCHRONIZE=false`、全局 TRUNCATE 跳过、全局清理许可关闭，并拒绝冲突配置；真实外部服务开关关闭。
4. **执行者先创建并记录独占可丢弃实例**：当前运行目录、服务 PID/启动事实、datadir 或等价归属证据、目标和实例标识。已有端口能连上、库名叫 e2e、某个 `/tmp` 路径或一份自己填写的匹配字符串都不单独证明可丢弃。没有安全目标先停止真实运行，继续实现/纯测试。
5. 只读预检核对 MySQL 实际端口/实例标识/库与期望，Redis 实例标识和选定 DB 与期望；记录脱敏摘要。不要为建立“所有权证明”先往未知实例写标记。预检连接无论成功/失败都关闭。
6. 预检成功后，以**同一已核验、显式构造的子进程 env**启动标准 runner。覆盖完整 DB/Redis 配置及安全开关，不能检查一个连接再让子进程继承另一份默认配置。检查与执行之间配置/服务变更则拒绝或重新核验。
7. 核对 globalSetup/globalTeardown 的真实配置加载。当前 Redis teardown 会按 env 文件名决定 FLUSHDB；本轮可使用明确的非默认 `acceptance.env` 使其跳过全库 FLUSH，同时仍独立绑定正确 Redis。文件名只用于避免不必要的清空，**不能替代服务归属与目标核验**。不凭空使用代码尚不支持的开关。
8. 参数只透传本轮需要的 core/精确文件/测试选择等受控参数，不执行任意 shell 字符串；子进程错误/信号/退出码准确传播。所有新建预检句柄关闭，超时不在子进程可能继续写入时删除资源。

可丢弃实例初始化另按已接受 Migration 完成，必须使用同一明确目标和完整进程配置；不能把清库演练指向保留副本，或用 synchronize 代替。此启动器不自动承担迁移、恢复、Seed、服务管理员等通用能力。

### 6.2 拒绝路径的验证边界

配置缺失/非法必须在连接和 spawn 前拒绝；目标不符允许必要只读预检，但在 Jest/global setup/写删前拒绝。测试应区分两者，不要求合法预检 SELECT 为 0。

错目标/漏环境反例只使用替身或本轮另一个明确可丢弃实例；**绝不连接真实 3306/6379 事故现场来复现**。验证拒绝时测试 runner 未启动、危险 SQL/FLUSHDB 为 0、错误及关闭可辨；正确配置则确认父子进程实际指向同一目标。

### 回归组织必须避免再造相同缺陷

- 优先在现有 L 驱动内复用精确子用例或独立永久验收命令，不引入一层无守卫的“兜底清场器”。自启动同一文件时，测试模式必须精确排除启动器本身，不能递归跑整组。

- 新测试若取得资源也必须进入本节资源图；评审“它自己的下一步如果失败”后才运行。纯 mock/无资源分支无需伪造归属。

- 负对照失败后，只有明确拥有者可在独占环境按创建证据处理残留；证据不足保留诊断或关闭本轮临时实例，不能凭固定名删除，也不能把额外人工处理记为 SUT 成功。
