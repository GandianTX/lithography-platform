## 四、运行前的检查：这一步不能省

1. 获取双方确认的分支/提交。Node按根目录.nvmrc配置（当前要求22.19.0）；首次安装按锁文件执行仓库npm run install:all，不随意重生成lockfile。
2. 准备个人、可丢弃且没有其他人同时使用的MySQL测试环境。目标库为lithography_e2e，结构已按当前Migration准备；不是“只创建一个空库就能运行”。没有建库条件时向A提出，不靠打开synchronize或关闭守卫解决。
3. 配置backend/env/.env.e2e：正确的DB连接、Redis连接、JWT/字段加密及其他必需测试配置；本地敏感值通过私密渠道取得，不写入Word、Git或测试截图。
4. Redis必须是允许清空的专用测试实例或专用逻辑库。实际执行后，现有全局收尾会对配置的Redis库执行FLUSHDB，清空其中全部键。逻辑库编号是否为15并不能证明它安全，需要确认其中没有需保留的开发/业务任务。
5. 本文命令跳过MySQL全库TRUNCATE，但规格仍会按归属/指纹清理自己的测试账号、组织、投稿及文件。跳过全库清理不等于整个过程只读。禁止在共享库、甲方库、正式库执行。
6. 使用本次交接专用终端；核对当前目录为仓库根目录后再复制命令。不要同时运行其他会使用同名测试账号/机型或相同Redis的测试。

如果测试库缺少表，先由A/B确认个人环境初始化方式。不要直接照旧onboarding的破坏性空库重建命令对已有库执行；旧文档里的14表是历史基线，当前业务结构为原14表加9表，新增迁移共10条。已有库不要删表重建来掩盖升级问题。

### 5.1 Bash/WSL命令

从仓库根目录开始，确认第四节的环境和清理范围后执行：

```bash
cd backend
task_handoff_dir=$(mktemp -d /tmp/pr0-handoff.XXXXXX)
E2E_SKIP_DB_CLEANUP=true E2E_ALLOW_DB_CLEANUP=0 E2E_ALLOW_PHYSICAL_CLEANUP=1 \
DB_NAME=lithography_e2e S7_SAMPLES_OUT="$task_handoff_dir/s7-samples.json" \
npm run test:e2e:file -- test/11-content-submission/frontend-response-samples.e2e-spec.ts
```

先确认测试命令退出码为0、两个场景通过，再核对JSON文件有39项。输出保存在本次新建的task_handoff_dir中，原始样例不要提交Git。若命令失败，文件可能不存在或只含部分记录，不能看见文件就认为复现成功。

### 5.2 Windows PowerShell命令

同样从仓库根目录开始；确认第四节后执行：

```powershell
Push-Location backend
$task_handoff_dir = Join-Path ([System.IO.Path]::GetTempPath()) ("pr0-handoff-" + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $task_handoff_dir | Out-Null
$env:E2E_SKIP_DB_CLEANUP = 'true'
$env:E2E_ALLOW_DB_CLEANUP = '0'
$env:E2E_ALLOW_PHYSICAL_CLEANUP = '1'

$task_test_exit = $LASTEXITCODE
if ($task_test_exit -ne 0) { throw "交接复现失败，退出码=$task_test_exit" }
$task_samples = @(Get-Content -Raw $env:S7_SAMPLES_OUT | ConvertFrom-Json)
if ($task_samples.Count -ne 39) { throw "样例不完整：$($task_samples.Count)/39" }
Pop-Location
```

运行后记录结果并关闭本次专用终端，避免环境变量残留影响其他测试。遇到失败不自行开启全库TRUNCATE、清空库、重建账号或放宽权限来凑通过。

### 5.3 四个执行开关分别代表什么

| 开关 | 含义 |
| --- | --- |
| DB_NAME=lithography_e2e | 指定预期测试库；实际连接库仍由守卫验证，不是仅看变量名 |
| E2E_SKIP_DB_CLEANUP=true | 跳过MySQL全库TRUNCATE，不跳过规格自身夹具写入/清理 |
| E2E_ALLOW_DB_CLEANUP=0 | 不授权MySQL全库清理 |
| E2E_ALLOW_PHYSICAL_CLEANUP=1 | 允许已核实归属的规格夹具物理清理；不代表允许清任意业务数据 |

上述开关不控制Redis FLUSHDB，Redis风险必须单独确认。输出临时目录在每次运行中新建，不覆盖其他人的结果；测试自己的临时上传目录在规格收尾按精确路径清理。
