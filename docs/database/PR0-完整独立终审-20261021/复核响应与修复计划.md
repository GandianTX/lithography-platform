- `content-submission-graphql.e2e-spec.ts`：`V-S7-1b/1c/1d` 依次消费 `V-S7-1a` 创建的 `submissionId`；`V-S7-3a` 消费 `V-S7-1d` 设置的 `publishedSubmissionId`，`V-S7-3b` 同用该 ID 做终态移除断言。

定向只跑后续 `it` 时，前置 ID 保持 0，断言会先失败或退化为无效 ID，与报告的最小触发一致。

## 修复计划与实施

1. **合并连续场景为单个 `it`（报告首选方案）**
   - GraphQL 规格：`V-S7-1a`–`1d` 合并为 `V-S7-1 普通资料全链：草稿 → 附件送审 → 退回重提 → 发布下载（单测独立）`，内部保留 a/b/c/d 命名步骤注释。
   - 前端样例规格：`A1`–`A4` 合并为 `A 普通资料全链…（单测独立）`；`B1`–`B3` 合并为 `B 案例全链…（单测独立）`。样例记录名 `A1.x`/`B1.x` 等保持不变。
2. **权限用例自行准备真实目标**
   - `V-S7-3a`：自行建稿并送审 v1，用该真实投稿做同组织他人、跨组织管理员的 `NOT_FOUND` 断言，不再依赖 `V-S7-1d`。
   - `V-S7-3b`：自行建稿、送审并通过，用该已发布投稿验证移除附件 409。
3. **消除同族跨 describe 依赖**
   - `B3` 自行创建并发布一个非案例资料，作为案例更正误用拒绝的真实目标；移除顶层 `materialPublishedDocumentId` 共享变量。
4. **重命名合并后重复的块级变量**（`updated`、`mine`、`reviewDetail(Response)`、`detailData`），仅改测试局部命名，不改断言。

未改 Entity、Migration、业务 API、状态机或 `src/`，未新增测试钩子。
